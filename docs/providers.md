# AI 공급자 지원 정책

## 현재 구현

- 기본 응답 경로는 **Gemma 4 로컬 답장 엔진**입니다.
- 엔진 입력은 현재 메시지, 최근 방 이력, 방 메모리, 자동 메모리, CSV로 가져온 과거 맥락입니다.
- 답장 말투 입력은 사용자 직접 예시, 수동 방 말투, 학습된 사용자 말투, 학습된 방 말투를 우선순위대로 합친 스타일 지침입니다.
- `ai_judge` / `smart` 모드에서는 확신이 낮으면 답장을 만들지 않고 건너뜁니다.
- `ai_judge` / `smart` 모드의 낮은 신호 메시지 스킵은 모델 로드보다 먼저 수행해, 모델이 없을 때도 불필요한 실패 로그를 만들지 않습니다.
- 기본 로컬 LLM 다운로드 경로는 **Gemma-4-E2B-it-LiteRT-LM** 입니다.
- 모델 파일은 다운로드 후 기대 크기와 SHA-256 해시를 검증한 뒤 `.part` 파일에서 최종 파일명으로 교체합니다.
- Hugging Face 토큰이 있으면 다운로드 요청에 Authorization 헤더를 붙여 gated/private 모델 접근에도 재사용할 수 있습니다.
- 회귀 테스트와 계측 테스트는 다운로드/저장공간 부담을 줄이기 위해 더 작은 **Qwen3-0.6B LiteRT** 테스트 모델을 사용합니다.
- 더 작은 모델은 빠르지만 한국어 품질이 약할 수 있고, 더 큰 모델은 품질이 좋아질 수 있지만 느려질 수 있습니다.

## 지원하지 않는 경로

- 소비자용 ChatGPT Plus/Pro 로그인 연동
- 제3자 앱에서 공급자 계정 세션을 그대로 재사용하는 OAuth 패스스루
- 소비자용 Gemini 유료 플랜 로그인 연동
- 공식 지원 범위를 벗어난 비공식 로그인 연동

## 현재 공급자 정규화

- 저장된 레거시 공급자 값 `openai`, `local`, `local-gguf`, `local-litertlm` 는 읽을 때 모두 `llm` / `gemma-4-e2b-it-litertlm` 으로 정규화합니다.
- 예전 OpenAI API Key, endpoint, authMode 값이 남아 있어도 실행 중에는 버리고 **로컬 Gemma 경로만** 사용합니다.

정상 제품 경로는 네트워크 의존 없이 기기 안의 저장 데이터를 재활용하는 **Gemma 4 로컬 응답 엔진**입니다. LiteRT-LM은 이 경로의 런타임 형식/엔진입니다.

Gemma 4 LiteRT-LM 경로는 현재 **실제 ARM64 Android 기기 검증이 필요**하며, 에뮬레이터에서는 지원하지 않습니다.

앱 UI는 에뮬레이터에서 Gemma/LiteRT-LM 실행과 모델 다운로드를 완료 기준으로 보지 않도록 차단합니다. 에뮬레이터에서는 빠른 단축 경로, 설정, 저장, 알림 수집 같은 비모델 경로만 검증하고, 실제 모델 로드/생성은 ARM64 실기기에서 확인합니다.

로컬 경로에서는 단순한 최근 사실 확인 질문(예: 최근 대화에 이미 나온 시간/일정 확인)에 대해 **모델 생성 전에 최근 대화에서 바로 답을 찾는 빠른 단축 경로**를 함께 사용합니다.

- primary prompt는 페르소나, 방 메모, 최근 대화를 더 넉넉한 예산으로 유지합니다.
- style_rewrite prompt는 사용자 직접 예시와 수동 방 말투를 최우선으로 다시 쓰는 후보를 만듭니다.
- human_style prompt는 "자동응답기"가 아니라 실제 사용자가 보낼 한 문장처럼 단어 선택, 길이, 반말/존댓말 느낌을 더 강하게 맞춥니다.
- compact prompt는 실패 대비 경로이지만 여전히 **최소 페르소나 + 방 메모 + 최근 대화 4개**를 남깁니다.
- emergency prompt도 0-grounding 으로 떨어지지 않고 **최소 페르소나 + 짧은 방 메모 + 최근 대화 2개**를 유지합니다.
- primary/style_rewrite/human_style/compact/emergency prompt 모두 스타일 지침을 유지합니다. 모델이 길게 실패할 때도 최소한 사용자 예시와 방 말투 일부가 남도록 예산을 나눕니다.
- primary/style_rewrite/human_style/compact 는 내부 candidate lane 으로 함께 예약하고 같은 품질 게이트에서 비교합니다. emergency lane 은 초기 후보가 모두 약할 때만 추가합니다.
- 앱은 Gemma가 만든 첫 응답을 곧바로 전송하지 않고, 규칙 기반 후보와 primary/style_rewrite/human_style/compact 후보를 함께 만든 뒤 길이, AI 메타 문구, 프롬프트 반복, 추측성 표현, 수동 방 말투 일치, 방 메모리 근거를 점수화해 가장 자연스러운 후보를 고릅니다.
- 수동 방 말투가 친한/반말 방이면 과한 존댓말 후보를 감점하고, 학교/팀/존댓말 방이면 반말 후보를 감점합니다. 이 감점은 모델 후보와 규칙 후보 모두 같은 기준으로 적용됩니다.
- 방 메모리나 최근 대화에서 일정/시간 같은 사실이 확실히 잡히면 모델 로드 전에도 근거 기반 후보를 바로 사용할 수 있습니다.
- `그거 됐어?` 처럼 지시 대상이 애매하고 최근 대화에 둘 이상의 후보 주제가 있으면, 모델 출력만 기다리지 않고 짧은 확인 질문 후보를 함께 평가합니다.
- primary/style_rewrite/human_style/compact 후보 품질이 낮으면 emergency 후보까지 만들고 같은 기준으로 다시 평가합니다.
- 현재 LiteRT-LM 엔진은 단일 네이티브 엔진 안정성을 우선해 `LlmEngine.generate()` 내부를 lock 으로 보호합니다. 후보 lane 은 코루틴 구조로 오케스트레이션하지만, 실제 네이티브 동시 실행은 실기기 안정성 검증 전까지 열지 않습니다.
- `maxTokens` 요청은 LiteRT-LM Kotlin API의 per-request 출력 토큰 제한 필드가 없어, 앱 레이어에서 출력 예산을 감시하고 예산 도달 시 생성을 중단한 뒤 정리합니다.

## 파인튜닝과 학습 정책

첫 버전의 개인화는 실제 모델 파인튜닝이 아니라 로컬 스타일 프로필과 프롬프트 그라운딩으로 구현합니다. 사용자 직접 예시와 수동 방 말투가 가장 높은 우선순위를 가지며, 학습된 말투는 언제든 끄거나 수정하거나 초기화할 수 있습니다.

학습된 말투는 샘플 수 기반 신뢰도 라벨과 함께 프롬프트에 들어갑니다. 신뢰도가 낮은 학습값은 확정 규칙이 아니라 보조 힌트로 취급하고, 사용자 직접 예시와 수동 방 말투를 계속 우선합니다.

실제 파인튜닝은 장기 과제로 유지합니다. 현재 기본 경로는 기기 안의 Gemma LiteRT-LM 실행과 로컬 저장 데이터를 사용하므로, 외부 로그 전송이나 원격 학습 의존성을 추가하지 않습니다.

구체적인 최근 측정값은 `docs/testing-quality.md` 의 로컬 수동 계측 결과를 기준으로 봅니다.
