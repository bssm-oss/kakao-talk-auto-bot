# 저장소 / 메모리 구조

## 로컬 저장

- `auto_reply_configs/` : 방별 자동응답 설정 JSON
- `room_state/` : 방별 최근 메시지 JSON
- SharedPreferences : 전역 UI 설정, 가져오기 메타데이터
- `StyleProfilePrefs` SharedPreferences : 학습된 사용자/방 말투 사용 여부와 수동 수정값
- `ReplyStatsPrefs` SharedPreferences : 수신/전송/스킵/실패 누적 횟수와 실패/스킵 원인별 카운트
- `ReplyCandidateStatsPrefs` SharedPreferences : 후보 응답 lane 별 생성/선택/빈 응답/저품질/latency 누적 집계. 프롬프트, 원문 응답, 방 이름, 발화자는 저장하지 않습니다.
- `redact_log_copies` SharedPreferences 값 : 로그 복사 시 방 이름, 발화자, 메시지 본문을 가릴지 여부. 기본값은 켜짐입니다.
- `logs/app.log` : 최근 로그. 기본 보관 한도는 최근 100줄이며, 로그 파일 수정 시각이 7일을 넘으면 다음 로그 append/read 시 자동 삭제합니다.

방별 자동응답 설정 JSON에서 `trigger.mode` 가 없거나 빈 문자열이면 `ai_judge` 로 해석합니다. `always` 는 사용자가 모든 메시지 모드를 명시적으로 저장한 경우에만 유지합니다.

방 상태 JSON을 읽을 때 파일이 손상되어 파싱할 수 없으면 해당 파일을 `.corrupt-<timestamp>` 이름으로 격리하고 빈 방 상태로 복구합니다. 손상된 파일 하나 때문에 알림 수집이나 답장 생성 전체가 중단되지 않아야 합니다.

## 메모리 종류

- **사용자 페르소나**: 전역 설정에서 관리
- **사용자 직접 예시**: 전역 설정의 `personaExamples` 로 저장하며 말투 지침에서 최우선 적용
- **방 메모리**: 방별 정책/말투/주의사항 저장
- **수동 방 말투**: 방별 설정 JSON의 `roomStyle` 로 저장하며 자동 추출 말투보다 우선 적용
- **학습된 사용자 말투**: CSV/방 이력에서 내 이름과 일치하는 발화를 요약하고, 필요하면 사용자가 수정값을 저장
- **학습된 방 말투**: 최근 방 이력에서 존댓말/반말, 응답 길이, 웃음/감탄 표현을 요약하고, 방별로 사용/수정/초기화 가능
- **최근 대화 흐름**: 실제 수신/발신 메시지 일부 저장
- **가져온 CSV 이력**: 과거 맥락을 방 상태에 병합

학습된 말투는 샘플 수에 따라 신뢰도를 함께 계산합니다. UI에는 `낮음`, `보통`, `높음`, `수동 수정` 같은 라벨과 0-100 점수, 샘플 수, 낮은 신뢰도 `보조 힌트` 표시를 함께 보여 사용자가 자동 추출값을 믿어도 되는지 판단할 수 있게 합니다. 전역 내 말투와 방별 말투 preview 모두 낮은 신뢰도 상태에서는 학습 원본 삭제 후 새 대화를 쌓으라는 reset 안내를 표시하고, 수동 수정 상태에서는 수정 초기화와 학습 원본 삭제의 차이를 구분해 보여줍니다. `수정 초기화` 는 수동 override만 지우는 동작이라 수동 수정값이 있을 때만 활성화되고, 자동 추출 말투가 잘못된 경우에는 방별 `학습 원본 삭제` 로 저장된 대화 이력과 자동 메모리 요약을 지워 다시 학습하게 합니다. 프롬프트에도 신뢰도 라벨, 0-100 점수, 샘플 수를 함께 넣고, 낮은 신뢰도 학습값은 섹션 제목에 `보조 힌트`, `충돌 시 무시`를 붙여 사용자 직접 예시나 수동 방 스타일을 덮지 못하게 합니다. 수동 수정값이 있으면 신뢰도와 관계없이 수동 수정이 우선합니다.

방별 학습 원본 삭제를 실행하면 해당 방의 저장된 최근 대화 이력과 자동 메모리 요약을 지웁니다. 방 메모리, 수동 방 말투, 대상 방 설정은 유지하므로 잘못 배운 자동 말투만 다시 쌓게 만들 수 있습니다.

## 말투 적용 우선순위

1. 사용자가 직접 적은 예시 문장
2. 방별 수동 말투
3. CSV/가져오기에서 찾은 내 발화 스타일
4. 앱에서 관측한 내 발화 스타일
5. 최근 대화에서 자동 추출한 방 말투
6. 최근 대화의 사실 관계

학습된 말투를 끄면 해당 자동 추출값은 프롬프트에 넣지 않습니다. 초기화는 사용자가 수정한 override만 지우고, 대화 이력에서 다시 계산 가능한 자동 추출값은 유지합니다.

## 새 방 자동 누적 규칙

- 사용자가 방을 따로 설정하지 않아도, 새로 관측된 방의 수신 메시지는 기본적으로 `room_state/` 에 누적됩니다.
- 이 누적으로부터 자동 메모리 요약도 함께 갱신됩니다.
- 단, **답장 활성화는 자동으로 켜지지 않습니다.** 새 방은 비활성 room target으로만 등록되고, 사용자가 켜야 실제 자동응답 대상이 됩니다.

`모든 채팅방에서 AI 답장` 이 켜져 있으면 기본 자동응답 설정을 사용하되, 실제 수신 방 이름으로 방 메모리, 자동 메모리, 학습된 방 말투를 다시 조회합니다. 따라서 특정 방 설정 파일이 없어도 해당 방에서 누적된 메모리와 말투가 프롬프트에 들어갈 수 있습니다.

같은 방/발화자/메시지 조합이 짧은 시간 안에 반복 알림으로 들어오면 답장 생성 작업은 한 번만 받습니다. 방별 답장 생성은 직렬화해 같은 방에서 답장이 중복되거나 순서가 쉽게 뒤집히지 않도록 유지합니다.

현재 구현은 빠른 단순화를 위해 파일 기반 저장을 사용합니다. 대규모 검색/요약이 필요해지면 SQLite/Room으로 확장 가능합니다.

로그 복사는 기본적으로 개인정보를 가린 텍스트를 클립보드에 넣습니다. 마스킹된 복사본은 방 이름, 발화자, 메시지 본문을 `<방 숨김>`, `<발화자 숨김>`, `<메시지 숨김>` / `<내용 숨김>` 으로 대체하되, 전송 실패 원인 같은 운영 reason 은 남깁니다. 정형 로그가 아닌 줄에서도 전화번호, 이메일, URL 은 각각 `<전화번호 숨김>`, `<이메일 숨김>`, `<URL 숨김>` 으로 치환합니다. `[방] 발화자: 메시지` 형태의 느슨한 카톡식 줄, `room=`, `sender=`, `msg=` 같은 key/value 디버그 줄, `"room"`, `"sender"`, `"message"` 같은 JSON 디버그 필드도 방/발화자/메시지 값을 가립니다. 답장 통계에 저장되는 알 수 없는 실패/스킵 reason 도 같은 민감정보 마스킹을 거친 뒤 저장합니다. 원본 로그 복사를 사용자가 선택할 수는 있지만, 복사 직전 방 이름, 발화자, 메시지 내용이 포함될 수 있다는 경고를 표시합니다. 로그 복사 기능은 외부 전송을 하지 않습니다.

로컬 로그 파일은 최근 100줄만 유지하고, 파일이 7일 넘게 갱신되지 않았으면 다음 로그 읽기 또는 쓰기 때 자동 삭제합니다. 로그 라인 자체에는 날짜가 아니라 시각만 들어가므로, 보관 기간 판단은 파일 수정 시각 기준으로 처리합니다.

메인 화면에서 최근 로그를 즉시 삭제할 수 있습니다. 로그 삭제는 로컬 로그 파일만 지우며, 방 메모리와 답장 통계는 유지합니다.

메인 화면의 응답 통계는 전송 성공률, 실패 원인, 스킵 원인을 함께 표시합니다. 실패가 있으면 최다 실패 원인을 우선 보여주고, 실패가 없으면 최다 스킵 원인을 표시합니다. 상세 줄에는 상위 실패/스킵 원인뿐 아니라 최근 실패 reason, 최근 스킵 reason, 마지막 전송/실패/스킵 이벤트의 상대 시각도 남겨 실기기에서 마지막으로 막힌 지점을 빠르게 볼 수 있게 합니다. `no session`, `no remoteInput`, `pendingIntent null`, `pendingIntent send failed`, `reply exception`, `ai quality rejected`, `ai generation exception`, `canned reply empty`, 전역 AI 답장 OFF, 방별 답장 OFF, 응답 설정 없는 방, 의미 없는 짧은 메시지 같은 이유를 분리해 실제 기기에서 어디가 자주 막히는지 볼 수 있게 합니다.

후보 응답 통계는 primary/style_rewrite/human_style/compact/emergency 및 규칙 기반 후보 source 별로 누적합니다. 저장되는 값은 source 이름, 생성 횟수, 선택 횟수, 빈 응답 횟수, 품질 게이트 미달 횟수, 총/최대 생성 시간뿐입니다. 이 값은 실기기에서 어떤 후보 전략이 느리거나 자주 비는지 확인하기 위한 운영 지표이며, 대화 본문이나 모델 raw output 을 장기 저장하지 않습니다. 샘플이 충분히 쌓인 source 는 다음 후보 선택에서 작은 신뢰도 보정값으로만 반영합니다.

`replyToRoomDetailed` 는 Boolean 대신 `SendResult(sent, reason)` 을 반환합니다. 기존 `replyToRoom` Boolean API는 유지하지만, 엔진 보조 로그와 통계는 상세 reason을 사용해 AI 생성 성공 후 카카오톡 전송 단계에서 막힌 원인을 추적합니다.
